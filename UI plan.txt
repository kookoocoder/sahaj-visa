**Comprehensive exploration of https://indianvisaonline.gov.in/**

This is the official Government of India portal (managed by Bureau of Immigration, Ministry of Home Affairs; designed/developed by NIC) for visa applications to India. It is the **only authorized** site for e-Visa, regular/paper visa applications, Afghan national visas, and e-Arrival Card. Strong warnings appear against agents, intermediaries, or fake sites that charge extra fees.

### High-Level Structure & Main Entry Points

**Homepage** (`/`):  
- Clear banner: “Authorized Portal for Visa Application to India”.  
- Key advisory text about passport + visa/e-Visa/OCI requirements.  
- Prominent note that foreigners and OCI cardholders must complete the **e-Arrival Card** online within 72 hours before arrival (also available on boi.gov.in or the official mobile app).  
- Four main action cards:  
  1. Regular/Paper visa by Indian Mission/Post → `/visa`  
  2. eVisa by Bureau of Immigration → `/evisa`  
  3. Visa on Arrival (Japan, South Korea, UAE under conditions) – info only, available at selected airports  
  4. Afghan Visa (Afghanistan nationals) → `/avisa`  
- Footer links to Digital India, india.gov.in, myGov, Study in India, social channels, and NIC.  
- Strong anti-scam advisory.

**Secondary official channels**:  
- **Indian Visa Su-Swagatam** mobile app (Android/iOS) – one-stop for e-Visa, regular visa form filling, Visa on Arrival forms, status tracking, ETA download, e-FRRO services (extensions, conversions, exit permits), Form-C, FTI-TTP for OCI, chatbot, multilingual support, location services, etc.  
- Cross-links to boi.gov.in, airsuvidha.civilaviation.gov.in (Self-Declaration Form), and ministry sites.

### Core User Workflows

#### 1. e-Visa (most common, fully online) – `/evisa/` or `/evisa/tvoa.html`

**Categories** (as listed):  
e-Tourist (30-day / 1-year / 5-year variants), e-Business, e-Medical, e-Medical Attendant, e-Student, e-Family, e-Transit, e-Miscellaneous.

**4-step process** (prominently displayed):  
1. Apply online – fill form + upload photo + passport bio page.  
2. Pay fee online (Credit/Debit card / Payment Wallet; SBI ePay & Axis Bank mentioned; ~2.5% transaction charges common).  
3. Receive ETA (Electronic Travel Authorization) by email.  
4. Print ETA and present at Immigration Check Post (e-Visa stamped on passport).

**Supporting tools on the page**:  
- Sample e-Visa Application (PDF)  
- Apply here for e-visa  
- Complete Partially Filled Application Form  
- Verify Payment / Pay e-Visa Fee  
- Print e-Visa Application  
- Check your Visa Status  
- Reupload Data  

**Side navigation / info**:  
- Countries/Regions eligible  
- Instructions for Applicant  
- FAQ’s  
- Authorized Immigration checkposts (airports + some seaports)  
- Payment Related / Payment Helpdesk  
- eVisa Helpdesk: (+91) 82 7808 7808, indian-evisa@gov.in  
- Useful links (MHA, MEA, Tourism, BoI, Incredible India)  
- Text-size controls (A+/A/A-)  
- “Chat with Mani” chatbot widget  

**Key constraints & rules** (from site + public guidance):  
- Apply minimum 4 days in advance (up to 30/120 days depending on type).  
- Passport valid ≥ 6 months from arrival + usually 2 blank pages.  
- Exact match of name, DOB, passport number, etc., to passport bio page.  
- Photo: JPEG, square (equal height/width), specific size (typically 10–300 KB), full face, white/light background, eyes open, no glasses in many cases.  
- Passport scan: clear colour bio page (MRZ readable).  
- Processing usually within 72 hours (often faster).  
- Ineligible: defence/military/security background, official/diplomatic passports in some cases, Pakistani origin (must use regular visa), etc.  
- Partial save + resume exists; re-upload for rejected photos/docs.

#### 2. Regular / Paper Visa – `/visa`

**3-step process**:  
1. Apply Online – fill & submit form (generates Application ID).  
2. Submit Documents – print signed form + supporting docs + passport at Indian Visa Application Centre (IVAC) or Indian Mission on scheduled appointment.  
3. Receive Passport/Visa – collect from Mission/IVAC or by post.

**Tools**:  
- Regular/Paper Visa Application  
- Complete Partially Filled Form  
- Check your Visa Status  
- Print Registered Application Form  
- Re-upload Document  

**Navigation**: Instructions, Authorized Entry/Exit Points, Visa Categories, Visa Processing Time, Visa Fee, Useful Weblinks.  

**Instructions page** details photo specs, one application per person, no post-submission edits, appointment scheduling (date/time + fee calculation including service charges/VAT), etc. Mission-specific rules still apply (users directed to individual Mission websites).

#### 3. e-Arrival Card – `/earrival`

Free service (arrival information only, **not a visa**). Must be completed within 72 hours before arrival.  

Form sections:  
- Quick Fill from Existing Data (passport + nationality + captcha)  
- Personal Details (name, nationality, passport, purpose)  
- Arrival Details (date, countries visited in last 6 days)  
- Address Details in India (state, district)  
- Contact Details (email, mobile, emergency)  
- Add Member (for groups/family)  
- Declaration + Submit  

Also available via the Su-Swagatam app and boi.gov.in.

#### 4. Afghan Visa Portal – `/avisa`

Dedicated for Afghanistan nationals. Categories: Business, Student, Medical, Medical Attendant, Entry, UN Diplomat. Similar tools (Apply, Complete Partially, Print, Status, Reupload). Contact: indianvisaonline-boi@mha.gov.in / same helpline.

### What the Site Currently Has (Strengths)

- Clear separation of e-Visa vs regular vs special cases.  
- Partial-save / resume functionality.  
- Status enquiry, print, re-upload, payment verification.  
- Helpdesk contacts and chatbot.  
- Sample form and basic instructions.  
- Multi-device claim (Android/iOS compatible).  
- Strong anti-fraud messaging.  
- Integration path to the more modern Su-Swagatam app.  
- Official branding and government seals.

### Major Gaps, Pain Points & What It Lacks (Critical for Redesign)

**UX / Design & Technical Reliability** (most frequently complained about in 2025–2026 reports):  
- Dated, cluttered interface; poor visual hierarchy.  
- Frequent crashes, session timeouts, data loss on “Next”, especially under load.  
- Mobile experience is poor (better suited to desktop; many users struggle on phones).  
- Strict, unforgiving upload rules with opaque error messages (“image not clear”, wrong format expectations that flip between JPEG/PDF).  
- Captcha and form validation feel brittle.  
- Character limits on travel history fields cause real problems for frequent travellers.  
- No robust progress indicator or auto-save feedback.  
- Inconsistent browser support notes (still mentions IE 9+).  

**Information Architecture & Guidance**:  
- Eligibility, fees, processing times, photo specs, and category activities are scattered or require digging into PDFs/side links.  
- No interactive eligibility checker or fee calculator on the main flows (exists more in the app).  
- Instructions are text-heavy and legalistic rather than guided/step-by-step with examples.  
- Pakistani origin / dual nationality / previous visa questions are easy to mis-answer.  
- No clear comparison table of visa types (duration, entries, allowed activities, fees by nationality).  

**Functionality Missing or Weak**:  
- No real-time photo validation / preview / crop tool before upload.  
- Limited multi-language support on the website itself (app is better).  
- No integrated appointment booking UX for regular visas beyond basic scheduling.  
- Weak group/family application flow (mostly one-by-one; e-Arrival has “Add Member”).  
- Status tracking is basic (no push notifications, detailed timeline, or estimated completion).  
- Payment failures / verification friction.  
- No in-form OCR assist from passport scan to auto-fill fields (despite OCR being used on backend for verification).  
- Limited accessibility (screen-reader, high-contrast, keyboard navigation).  
- No clear offline/resume across devices beyond partial form.  
- Helpdesk is phone/email only; chatbot is basic.  
- No proactive alerts for common rejection reasons before submission.  

**Process & Trust Issues**:  
- High rejection rates driven by photo/passport quality and data mismatches (users report 30–40% preventable).  
- Users must still visit Mission websites for regular visa details → fragmented experience.  
- e-Arrival + Self-Declaration Form (separate Civil Aviation site) create multiple pre-arrival steps.  
- No transparent SLA or average processing time shown dynamically.  

### Opportunities for Redesign & Improvement (Prioritized)

1. **Modern, mobile-first UI** – Clean card-based flows, progressive disclosure, sticky progress bar, dark mode, true responsive design.  
2. **Smart form engine** – OCR passport scan → auto-fill + highlight mismatches; real-time photo checker with live preview, crop, and compliance scoring; dynamic fields based on nationality/visa type/occupation.  
3. **Guided wizard + eligibility tool** – Start with nationality + purpose → recommend exact visa type, show fees, timelines, required docs, and sample successful photos.  
4. **Reliability & performance** – Robust auto-save, offline capability for form filling, better error recovery, CDN/queue handling for peak loads.  
5. **Unified experience** – Deeper integration or seamless hand-off with Su-Swagatam app; single dashboard for all applications, e-Arrival, FRRO, and status.  
6. **Better support** – Contextual help, video walkthroughs, expanded multilingual content, smarter chatbot, in-app ticket system.  
7. **Transparency** – Live average processing times, rejection reason analytics (anonymized), clear fee breakdown before payment.  
8. **Accessibility & inclusion** – WCAG compliance, larger touch targets, language selector, simplified language options.  
9. **Group applications** – Proper multi-applicant flow with shared address/payment.  
10. **Post-approval** – Digital wallet for ETA, calendar reminders, airport guides, and easy re-application for extensions.

**Summary of current state**: Functionally complete for core visa application and status checking, with decent coverage of categories and official warnings. However, the experience is brittle, dated, and friction-heavy—especially on mobile and around document uploads—leading to high user frustration, repeated attempts, and reliance on third-party “helpers” (which the government explicitly discourages). The Su-Swagatam app already shows the direction of a better integrated experience; the website needs to catch up in usability, reliability, and guidance while remaining the authoritative source.

This analysis is based on direct browsing of the live site (homepage, e-Visa, regular visa, e-Arrival, Afghan portal, instructions, status pages) plus cross-referenced public documentation and user reports as of late 2026. Specific form fields and exact photo pixel requirements can shift, so a redesign should include ongoing content management for rules.

### 1. What is UX4G?

UX4G is the **official Government of India Design System** (v3.x) for building consistent, accessible, citizen-facing digital services. It provides:

- Design tokens (colours, spacing, typography, radius, shadows, etc.)
- Ready-to-use components (buttons, forms, cards, alerts, etc.)
- Content patterns (labels, errors, helper text, consent language)
- Iconography (Material Symbols)
- Spacing & layout system
- Accessibility baseline (WCAG 2.1 AA)
- AI agent skills (`SKILL.md` + `Design.md`) so any AI coding tool follows the same rules

It is the **mandatory contract** for new or redesigned government websites/apps. Using it ensures compliance, consistency with other GoI services, and better citizen experience.

**Current authoritative packages (as of Aug 2026):**
- Web: `npm install ux4g-web-components` (v2.0.1) or CDN `https://cdn.ux4g.gov.in/UX4G@3.1.0/`
- Flutter: `ux4g_flutter_components` (v1.3.0)
- Docs: https://doc.ux4g.gov.in/web/ and /flutter/
- Figma: UX4G Design System 3.0

**Never use** legacy/stale sources (old Bootstrap docs, netlify mirrors, deprecated Flutter package).

#### Phase 2: Foundations Application
**Spacing & Layout**
- Use base-4 scale (`--ux4g-space-1` = 2px … `--ux4g-space-15` = 120px)
- Prefer semantic roles: `--ux4g-inline-*`, `--ux4g-stack-*`, `--ux4g-padding-*`, `--ux4g-section-*`
- Max content width: 1200 px (desktop), 1320 px (XL)
- Body text ≤ ~720 px width
- Touch targets ≥ 44×44 px, ≥ 8 px gap

**Tokens**
- Never hard-code colours / spacing / radius / fonts
- Always use `--ux4g-*` custom properties
- Typography: Noto Sans family, semantic sizes (`--ux4g-fs-16`, etc.)
- Radius: none / sm / md / lg / full
- Support light + dark themes via `data-theme="light|dark"`

**Iconography**
- Use **Material Symbols Outlined** (default) or Rounded
- Categories ready for visa: Documents, Identity, Payments, Security, Alerts, Forms, Travel
- Always pair icons with text labels for primary actions
- Size via `.ux4g-fs-*` classes
- Semantic colours only (success / error / warning / info)
